## 1. 项目概述

### 1.1 产品定位

**Code Agent CLI** — 一款终端原生（Terminal-Native）的编码智能体工具，专注服务**中国开发者**，深度适配国产大模型，提供多模式对话、工具调用、MCP 协议、RAG 等能力。

### 1.2 核心价值主张

```
对开发者：在终端中用自然语言驱动编码，支持你最想用的国产模型
对团队：统一的 AI 编码入口，轻量无依赖，开箱即用
```

### 1.3 用户需求映射

| 用户需求           | 对应功能点                         | 优先级  |
| -------------- | ----------------------------- | ---- |
| 想用国产模型做编码智能体   | 多模型接入适配                       | P0   |
| 让 AI 替我读代码、改代码 | 工具调用（读/写/搜索文件）                | P0   |
| AI 能连接外部工具和服务  | MCP 协议支持                      | P0   |
| 不同场景用不同交互方式    | 多种对话模式（plan/auto/edit/normal） | P0   |
| 在终端里灵活控制       | CLI 命令体系                      | P0   |
| AI 能理解整个项目上下文  | RAG                           | P1   |
| AI 能执行终端命令     | 终端能力                          | P1   |

### 2.4 市场判断：值得做吗？

| 评估维度 | 评分    | 说明                            |
| ---- | ----- | ----------------------------- |
| 市场规模 | ⭐⭐⭐⭐  | 中国开发者约 1000 万+，AI 编程工具渗透率快速提升 |
| 竞争强度 | ⭐⭐⭐⭐  | 竞争激烈但有差异化空间（CLI + 国产模型组合是蓝海）  |
| 进入门槛 | ⭐⭐⭐   | 技术门槛中高，需要 LLM 工程经验 + CLI 工具经验 |
| 增长趋势 | ⭐⭐⭐⭐⭐ | AI 编码工具年增长率 50%+，仍在早期         |
| 变现潜力 | ⭐⭐⭐⭐  | 开源引流 + API 按量/企业订阅是可行路径       |
| 技术风险 | ⭐⭐⭐   | 国产模型能力差距在缩小但仍需适配成本            |

**结论：✅ 值得做。**  
核心逻辑：国际市场已验证 CLI 原生编码 Agent 模式（Claude Code 133K stars, Codex CLI 92K stars），国内市场此方向几乎空白。如果能在"开源 + 国产模型深度适配 + 终端原生体验"三角上建立优势，有明确的差异化竞争力。

## 3. 可行性评估

### 3.1 技术可行性

| 需求        | 技术可行性 | 说明                                     |
| --------- | ----- | -------------------------------------- |
| 国产模型接入    | ✅ 高   | 国内模型基本兼容 OpenAI API 格式，接入成本低           |
| 工具调用      | ✅ 高   | Function Calling 已成熟，参考 Cline/Aider 实现 |
| MCP 协议    | ✅ 高   | MCP 协议标准已发布，有参考实现                      |
| 多对话模式     | ✅ 高   | 状态机设计，模式切换逻辑清晰                         |
| CLI 命令    | ✅ 高   | Node.js 生态有 commander/yargs 等成熟方案      |
| RAG       | ✅ 中   | 可用向量数据库（SQLite + 嵌入模型）实现轻量 RAG         |
| 终端能力（PTY） | ⚠️ 中  | 跨平台 PTY 实现较复杂，Windows 需特别处理            |

### 3.2 资源可行性

- **开发语言选择**：TypeScript（生态丰富、社区大、开发效率高）或 Rust（性能好、单文件分发，如 Codex CLI）
- **团队规模**：1-2 人可完成 MVP（核心功能约 2-3 个月）
- **API 成本**：开发测试阶段月均 $50-100 的 API 费用

### 3.3 市场可行性

- **目标用户基数**：国内 CLI 开发者群体持续增长，Node/Go/Rust/Python 开发者是核心受众
- **付费意愿**：个人开发者愿为工具付费（$5-10/月），企业端 $15-30/人/月
- **竞品壁垒**：品牌认知、数据积累、生态锁定是主要壁垒，产品差异化是突破点

## 5. 功能需求详述

### 5.1 P0 — 核心功能（MVP 必做）

#### 5.1.1 国产模型适配

**要求**：

- 开箱即用支持主流国产模型 API
- 支持用户自定义 API Endpoint
- 统一模型切换命令

**目标模型列表**：

| 厂商     | 模型                              | 接入方式          |
| ------ | ------------------------------- | ------------- |
| 深度求索   | DeepSeek-Coder / DeepSeek-V3/R1 | OpenAI 兼容 API |
| 智谱 AI  | GLM-4 / CodeGeeX4               | OpenAI 兼容 API |
| 阿里云    | Qwen-Coder / Qwen2.5-Coder      | OpenAI 兼容 API |
| 字节跳动   | 豆包 / Doubao-Pro                 | 自研 API        |
| 百度     | ERNIE 4.5 / ERNIE-Speed         | 自研 API        |
| 科大讯飞   | 星火 4.0                          | 自研 API        |
| 月之暗面   | Moonshot / Kimi                 | OpenAI 兼容 API |
| 零一万物   | Yi-Lightning                    | OpenAI 兼容 API |
| 硅基流动   | 代理多种开源模型                        | OpenAI 兼容 API |
| Ollama | 本地开源模型                          | OpenAI 兼容 API |

#### 5.1.2 工具调用

**核心工具集**：

| 工具             | 功能      | 说明          |
| -------------- | ------- | ----------- |
| `read_file`    | 读取文件内容  | 支持行范围、语法高亮  |
| `write_file`   | 写入/覆盖文件 | 需用户确认       |
| `edit_file`    | 精确编辑文件  | 基于搜索替换      |
| `create_file`  | 创建新文件   | 自动创建目录      |
| `delete_file`  | 删除文件    | 需用户确认       |
| `glob_search`  | 文件模式搜索  | 支持 glob 通配符 |
| `grep_search`  | 文件内容搜索  | 支持正则        |
| `list_dir`     | 列出目录    | 递归/深度控制     |
| `run_terminal` | 执行终端命令  | 沙箱/用户确认     |
| `web_fetch`    | 获取网页内容  | 获取文档等       |
| `web_search`   | 网页搜索    | 获取最新信息      |

**安全策略**：

- 写文件/删文件/执行命令需用户确认（默认）
- `--yolo` 模式可跳过确认（自主模式）
- 敏感文件（.env、config 等）操作需二次确认

#### 5.1.3 MCP 协议支持

**要求**：

- 原生支持 MCP stdio/SSE/HTTP 传输协议
- 支持 `mcp.json` 配置（兼容 Cursor/Claude/Cline 格式）
- MCP 工具自动发现和注册
- 提供 `mcp add/remove/list` 管理命令
- 用户可通过配置文件添加自定义 MCP server

**示例配置**：

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@anthropic-ai/mcp-playwright"],
      "env": {}
    },
    "filesystem": {
      "command": "npx",
      "args": ["@anthropic-ai/mcp-filesystem", "/path/to/project"],
      "env": {}
    }
  }
}
```

#### 5.1.4 多种对话模式

**模式设计**：

| 模式         | 名称   | 行为                    | 适用场景         |
| ---------- | ---- | --------------------- | ------------ |
| **plan**   | 计划模式 | 先输出实现计划 → 用户确认 → 逐步执行 | 复杂功能开发、重构    |
| **auto**   | 自主模式 | AI 自主规划、自主执行、自主修正     | 有经验的开发者、简单任务 |
| **edit**   | 编辑模式 | 只接受文件编辑请求，不执行命令       | 只想改代码不想执行命令  |
| **normal** | 普通模式 | 标准问答 + 按需调用工具         | 日常使用、学习      |

**模式切换**：

- 交互式切换：`/mode plan`、`/mode auto`
- Tab 键快速轮询：TUI 模式下按 Tab 依次切换 Normal → Auto → Plan → Edit → Normal，状态栏实时显示当前模式
- 启动时指定：`code-agent --mode plan`
- 会话中自动触发：AI 检测复杂任务时建议切 plan 模式

#### 5.1.5 CLI 命令体系

| 命令                                  | 功能           |
| ----------------------------------- | ------------ |
| `code-agent`                        | 进入交互式 TUI 模式 |
| `code-agent -p "描述任务"`              | 非交互模式，直接执行   |
| `code-agent --mode plan`            | 指定模式启动       |
| `code-agent --model deepseek-coder` | 指定模型启动       |
| `code-agent init`                   | 在当前项目生成配置文件  |
| `code-agent config`                 | 查看/编辑配置      |
| `code-agent config set key value`   | 设置配置项        |
| `code-agent config list`            | 查看所有配置       |

**Slash 命令（对话中）**：

| 命令        | 功能                    |
| --------- | --------------------- |
| `/mode`   | 切换对话模式                |
| `/model`  | 切换模型                  |
| `/usage`  | 查看 token 用量和费用估算      |
| `/clear`  | 清空当前对话                |
| `/goal`   | 设置长期目标，持续执行直到完成       |
| `/loop`   | 循环执行当前任务，自动修正         |
| `/cost`   | 查看本次会话 API 调用费用       |
| `/status` | 查看当前会话状态（模式、模型、上下文大小） |
| `/help`   | 查看帮助                  |
| `/undo`   | 撤销上一步操作               |
| `/save`   | 保存当前对话                |
| `/load`   | 加载历史对话                |

### 5.2 P1 — 增强功能（V2）

#### 5.2.1 RAG

**需求**：

- 自动索引项目代码库（支持.gitignore 过滤）
- 支持向量检索 + 关键词混合检索
- 支持自定义 RAG 配置（索引范围、更新策略）
- 支持 @file / @function / @class 符号引用
- 增量索引，不重复消耗

**技术选型建议**：

- 嵌入模型：使用本地轻量模型（如 BGE-small-zh）进行嵌入
- 向量存储：SQLite + sqlite-vec 扩展，免部署
- 分块策略：基于 AST 的语义分块（参考 Aider Repo Map）

#### 5.2.2 终端能力

**需求**：

- AI 可直接在终端中执行命令（需用户确认）
- 支持命令输出流式查看
- 支持长时间运行命令的超时和取消
- 自动检测命令失败并建议修复
- 支持 PowerShell/Bash/Zsh/Fish 多 Shell

**安全设计**：

- 命令执行白名单/黑名单配置
- 自动屏蔽危险命令（rm -rf /、dd 等）
- 命令预览 + 拦截确认机制

### 5.3 P2 — 扩展功能（V3+）

- **子代理（Sub-agent）**：并行执行多个独立任务
- **Computer Use**：控制浏览器、桌面应用
- **多语言 TUI**：中文/英文界面

## 6. 差异化亮点设计

### 6.1 核心差异化策略

```
国产模型 × CLI 原生 × 开源 × 多模式对话
```

### 6.2 亮点功能详细设计

#### 亮点一：模型路由器（Model Router）

**概念**：根据任务类型自动选择最优模型。

```
代码生成 → DeepSeek-Coder（成本低，代码能力强）
复杂推理 → GLM-4 / Qwen-Plus（推理能力强）
简单问答 → 豆包 / Yi-Lightning（速度快成本低）
本地敏感 → Ollama（数据不出本机）
```

**实现方式**：

- 用户在配置中定义路由规则
- 支持任务感知路由（AI 自动判断任务类型）
- 支持手动覆盖路由

**价值**：成本最优 + 质量最优，同一对话可动态切换底层模型。

#### 亮点二：模式自动推荐（Smart Mode）

**概念**：AI 感知任务复杂度，自动建议切换模式。

```
检测到：用户要求"给整个项目加登录功能"
→ AI 建议："该任务较复杂，建议切换到 plan 模式"
→ 用户确认后自动生成实施计划
```

**价值**：降低用户认知负担，新手不用纠结该用什么模式。

#### 亮点三：成本管家（Cost Guardian）

**概念**：实时追踪 API 费用，用数据帮用户省钱。

```
- 每次调用后显示估算费用
- 每日/周/月费用统计
- 建议更经济的模型组合
- 费用超标自动告警
- /cost 命令查看详细账单
```

**价值**：国产模型价格差异大，帮用户省钱是实实在在的卖点。

#### 亮点四：智能上下文管理（Context Manager）

**概念**：自动管理上下文窗口，避免 token 溢出。

```
- 自动压缩历史对话（摘要化）
- 滑动窗口 + Token 预算控制
- 关键上下文始终保留（当前文件、项目结构）
- 用户可通过 /context 查看和管理上下文
```

**价值**：长对话场景体验好，不丢失关键信息。

#### 亮点五：项目模板生成器（Project Scaffold）

**概念**：一句话生成完整项目脚手架。

```
用户：/scaffold 给我创建一个 Python FastAPI 项目，有 JWT 认证和 MySQL 配置
AI：生成完整的项目结构、代码文件、配置文件、依赖文件
```

**价值**：新项目启动效率极大提升，展示能力最直观。

#### 亮点六：交互式配置向导（Setup Wizard）

**概念**：首次使用时的配置引导，降低上手门槛。

```
$ code-agent init

  ╭─────────────────────────────╮
  │  Code Agent Setup Wizard 🪄  │
  │                             │
  │  选择模型：                  │
  │  ○ DeepSeek (推荐)          │
  │  ○ 智谱 GLM                  │
  │  ○ 阿里 Qwen                 │
  │  ○ Ollama (本地)            │
  │  ○ 手动配置                 │
  │                             │
  │  API Key: [___________]     │
  ╰─────────────────────────────╯
```

**价值**：降低配置门槛，新用户 1 分钟上手。

| **PTY 终端**  | node-pty / xterm-headless      | WinPTY          | 跨平台终端模拟           |

## 8. 风险与应对

| 风险         | 等级   | 影响            | 应对策略                                     |
| ---------- | ---- | ------------- | ---------------------------------------- |
| 国产模型能力不足   | 中    | 用户体验差         | 支持用户 BYOK + Ollama 本地模型；模型路由选最佳模型        |
| API 不稳定/限流 | 中    | 服务不可用         | 内置重试 + 容错 + 多 Provider 自动切换              |
| 竞品快速跟进     | 高    | 差异化消失         | 开源建立社区粘性；深耕 CLI 体验壁垒                     |
| 用户获取困难     | 高    | 增长缓慢          | 开源 + 社区驱动；打造教程和案例内容                      |
| 安全风险（命令执行） | 高    | 用户机器受损        | 多层确认机制；沙箱隔离；危险命令检测                       |
| 跨平台兼容      | 中    | Windows 用户体验差 | 优先 macOS/Linux（完善）；Windows 沙箱隔离（文件操作限制在沙箱目录内，防止误伤系统文件） |
| 变现困难       | 中    | 项目不可持续        | 开源免费 + 企业版付费 + 云服务增值                     |

## 10. 总结与建议

### 10.1 是否值得做？

| 维度       | 结论                                       |
| -------- | ---------------------------------------- |
| **市场机会** | ✅ 国产模型 × CLI 原生编码 Agent 是明确的蓝海方向         |
| **竞争格局** | ✅ 国际已验证模式（Claude Code 133K stars），国内无直接对标 |
| **技术可行** | ✅ 核心功能基于成熟技术栈，MVP 可 2 个月内完成              |
| **变现路径** | ✅ 开源引流 + 企业版付费 + 云服务增值，路径清晰              |
| **个人回报** | ✅ 独立开发者打造开源作品，对职业发展和技术影响力都有帮助            |

**整体结论：强烈建议启动。**  
在国内 AI 编程工具从"插件时代"向"Agent 时代"迁移的窗口期，CLI 原生路线与国产模型深度适配的组合，是目前最适合独立开发者切入的方向。

### 10.2 关键成功要素

1. **先发优势**：尽快推出 MVP，在国产 CLI Agent 赛道建立品牌认知
2. **模型质量**：和 2-3 家国产模型厂商建立合作，确保 API 稳定性和质量
3. **社区建设**：开源 + 文档 + 教程，早期用户至关重要
4. **体验打磨**：CLI 工具的用户对体验极其敏感，响应速度和交互设计是生命线
5. **差异化坚持**：不要试图做"国产 Claude Code"，而要做"最适合中国开发者的终端编码 Agent"

### 10.3 没必要做的（避坑建议）

- ❌ 不要做 IDE 插件（那是 Red Ocean，竞争白热化）
- ❌ 不要做自己的模型（成本太高，专注应用层）
- ❌ 不要一上来就做 JetBrains 支持（成本高收益低）
- ❌ 不要过早商业化（等社区口碑建立后再考虑）
- ❌ 不要承诺 100% 代码正确（应设计"人机协作"的交互流程）
